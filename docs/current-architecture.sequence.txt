note over Browser,Redis: Public listener and live-radio path
Browser->Funnel: HTTPS page, API, SSE, and live-audio requests
Funnel->Proxy: Forward to active loopback deployment
Proxy->API: Route to api or api-next
API->DB: Read/write sessions, requests, reactions, catalog and outbox
API-->Browser: HTML/JSON; SSE and MP3 streams

DB->Dispatcher: Unfinished durable outbox records
Dispatcher->SQS: Publish reaction and work messages
SQS->Workers: At-least-once delivery
Workers->DB: Persist job and catalog outcomes
Workers->Redis: Project reactions and publish events
DB->Station: Select eligible track and cached introduction
Station->DB: Record play before transmission
Station->Redis: Publish paced MP3 chunks and track events
Redis->API: Live audio, SSE snapshots and demand state

note over Browser,Files: Telemetry producers never wait for Elasticsearch or OpenSearch
Browser->API: POST /api/activity (cookie-bound batch)
API->API: Validate origin, age, schema, actions and rate
API->Telemetry: Enqueue sanitized browser event
API-->Browser: 202 Accepted
API->Telemetry: Enqueue API latency/outcome and domain events
Workers->Telemetry: Enqueue job lifecycle and worker errors
Telemetry->DB: Enrich event with allowlisted track metadata
Telemetry->Files: Append ECS JSON; rotate bounded files

loop Every 2 seconds
  Observer->DB: Read durable plays, requests, jobs and downloads
  Observer->Observer: Deduplicate outcomes in observer.sqlite
  Observer->Telemetry: Enqueue newly observed lifecycle events
end

par Independent ELK ingestion
  Files->ELKPipe: Tail JSONL using ELK sincedb
  ELKPipe->ES: Bulk index by event.id into daily index
  Kibana->ES: Query radioworkx-events-*
else Independent OpenSearch ingestion
  Files->OSPipe: Tail same JSONL using separate sincedb
  OSPipe->OS: Bulk index by event.id into daily index
  OSD->OS: Query radioworkx-events-*
end

note over ES,OS: Both stores retain their own data and ingestion state; current policy deletes activity indices after 30 days
